# CHANGELOG

All notable changes to this project will be documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

This file starts here; anything before the entries below is only in the git history.

## Unreleased

### Added

- **Der Content-Bereich kann jetzt alles anlegen, was diese App kennt**: the CMS's editing screen is used here as it comes, and this app served it only the handful of endpoints it happened to need — enough to read an entry and to save one, and nothing else. So there was no way to create anything: the button was there, and what it asked for did not exist, which the app answered with its own start page rather than with an error. The CMS's API is now mounted whole, so making something works, and with it everything else that screen has always been able to do — the list of what is saved and not yet published, releasing a batch of it at once, the record of what has happened to an entry, and the search behind it. Films, people, journeys and artworks are offered by name like any other kind of content, and each is stored in the form it declares rather than in the one a screen guessed at.

- **Ein eigenes Recht für den Zugriff auf den Medienspeicher**: the preview above needs to read a file that no entry names yet, so the entry's own permissions cannot decide who may see it and something had to stand in their place. That was first the entitlement for the editor area — "you may be shown the content section" — which is an answer to a different question: an area says what a visitor may *reach*, and this asks what somebody may *do* while writing. There is now a right of its own for it, `media.read`, which can be granted and withdrawn without touching either what somebody may author or what appears in their menu, and which can be narrowed to a folder. Accounts holding everything are unaffected. An account that edits films and holds nothing else needs the new right, or the preview stays empty for it.

- **Die Vorschau im Film-Editor spielt, sobald der Pfad dasteht**: the player in the film editor asked for the film by the entry's id, which means the entry has to exist, be saved, and be published and indexed before anything can be seen. So writing a new film went: type the path to the file, save, publish, and only then find out whether the path was right. The player now plays the file named in the Key field itself — nothing has to be saved first, and correcting a mistyped path changes the picture immediately instead of after a release. The media store is offered the same way the mediathek, the music and the magazines are: as a shelf, reachable only within its own directory, and only by somebody holding the right to read it.

- **Das Kirchenjahr und die Arbeitszeit sind zurück**: two pieces from the old cloud11 — the calendar of named days, and the working-time model behind the Kalender pages — lived in a shared library repository that nothing here used. They are part of this app now. The first knows every named day of a year: Easter is calculated, and the sixty-odd days that hang off it or off a rule (the fourth Thursday of November, the last Sunday of March, the fourth Sunday before Christmas) are worked out from it. The second is what a year of work is made of: a year holds months, a month holds days, a day holds the stretches somebody actually worked, and the day is where the arithmetic is — hours at the desk, less the breaks, against what was owed.

  Neither is wired to a screen yet. The working-time half has no storage: the original kept its own database with credentials written into it, and this app keeps its own elsewhere, so what is here is the part that was expensive to work out and not the part that is merely typing. Both are now covered by tests, which is also how three long-standing oddities came to light and are written down where they are: a day the calendar merely has a *name* for — Valentinstag, Halloween, Black Friday — is treated as a public holiday when a year is set up, is nevertheless still expected to be worked, and every day of every year is filed under the same account regardless of whose year it is. None is fixed here; each is a decision about whose calendar this is rather than something to settle while moving code.

  The old storage and the old web layer came along too, but only to be read: the queries, the table definitions they were written against, and the endpoints that sat on top sit beside the working-time model under their own names, excluded from the build, each with a note on what was checked about it — three of the four ways of writing a day could never have worked, which is the likely reason these pages never had a backend. Kept because they are the only surviving description of the shape this data had, and because the same file turns out to describe the database that came before them as well, which is worth having if the original application is ever found again.

- **Die Content-API beschreibt sich selbst**: what the content endpoints accept and answer is now readable at `/content-api/v1/docs`, worked out from the code that serves them rather than written down beside it.

### Changed

- **Eine Leiste statt zweier, und die Bereiche liegen jetzt im Menü**: the top of the screen was two different things — a strip with the areas written across it on a computer, and on a phone a band with nothing in it but a way back, drawn by something else entirely and sitting a few pixels away in the code. They are one thing now, and it holds the same four things at every width: the way back, what the page is called, whatever that page offers, and the round button in the corner.

  The areas left the strip. They were a row of dropdowns, one per subject, which only ever fitted because they were grouped — and the menu behind that round button holds the same list with room to show the grouping properly, under Verwaltung, Medien and Familie. Reaching an area costs what it always did: open, then choose. What the strip gained in exchange is the name of the page you are on, and the buttons that belong to it — the two that size a video, for instance, which used to sit in a bar of the page's own with a second way back beside them.

  On a phone the round button moved from the bottom corner to the top right, into that strip. It is further from a thumb, and it is now the only navigation there is, so it no longer scrolls away.

- **Jede Seite kann sagen, welche Farbe der Rand oben hat**: the strip at the top is also what an installed iPhone paints its status bar from, so the two are set as one colour and a page chooses it — along with whether what is written on it should be light or dark, which is stated rather than guessed at, because the system picks its own clock and battery colour from the same surface and will not be told. Zeitschriften is blue; everything else is black.

- **Die App baut wieder ohne fremde Zugänge**: an unused package sat in the tree — an older way of talking to the file store, written before the one in use today and reachable from nothing. It was the only thing still tying this app to three outside libraries, one of them on a private server belonging to another company. Building the app therefore required an account there, which is no business of a family website. All three are gone with it, along with a fourth that had been listed as needed and never was.

  Everything that remains was brought up to date at the same time, and two independent checks now report nothing known to be unsafe in any of it. Several of the parts had faults found in them since they were last touched: one let a specially made web address exhaust the server's memory through the search filters on the artworks page, one could be tricked into running the wrong database query, and one — the library that reads and writes Git repositories, which the content store is built on — allowed a specially made repository to write a file outside the place it was meant to and have it run. Nothing about this app did any of that; the flaws were in the machinery underneath.

  Three of the libraries went entirely at the same time. The app carried the whole of Docker's engine repository — nearly seven megabytes, fetched on every clean build — for fifty lines that write the running process's number to a file so a second copy of the server refuses to start; that is now ours, in about the same number of lines and with tests. A second, unused database driver was being registered at startup, left over from before the move to the current one. And the last of three competing ways of reporting an error is gone, so there is now one, used everywhere. Nothing the app does has changed; what changed is that checking it out and building it now requires nothing but this repository.

- **Speichern veröffentlicht nicht mehr sofort**: saving an entry used to publish it in the same breath, so there was no such thing as work in progress — every save was live. The CMS's own model applies now: a save is kept as yours until it is published, several of them can be released together as one change, and what is waiting is listed in the bar above the content. This is what the drafts and batches in that screen have always referred to; here they referred to nothing.

- **Die Kopfleiste hat jetzt eine Maximalbreite**: on a wide screen the wordmark sat in one far corner of the window and the round menu button in the other, a foot apart from anything they belonged with. What is in the strip now stops at a fixed width and is centred; the strip's colour still runs to the edges of the window, because it is still the strip.

  The strip also sits lower and the name is smaller: the row is taller than the name needs and its contents sit at its foot, so the extra height is whitespace above them and the line stays close under them. The line crosses the round button about two thirds of the way down rather than through its middle. The cloud at the end of the name is stated as the size of the type rather than as a number of pixels that happened to match it, so the two can no longer be changed apart.

  The black line under it changed with them. It used to run the full width of the window with a hole punched in it where the button crossed — a line that went too far, patched. It now simply begins where the wordmark begins and stops short of the button, which is what was wanted all along and only became possible once the line stopped being what separates the strip from the page. The band below does that now.

- **Zwischen Kopfleiste und Seite liegt jetzt ein Übergang**: the page began hard against the strip at the top, so on a page whose content starts with a block of colour — the front page's wall of tiles does — the two read as one and the join was somewhere the eye could not find. There is now a band between them, two centimetres of gradient running from the strip's own colour down to the page's, so the two meet by fading rather than by a line. Each page can say how tall it should be, or ask for none at all, and can name its own background colour — the band arrives at whatever that is, since a band fading to a colour the page is not would put back the line it exists to remove. The band belongs to the page rather than to the strip, so a strip that stays put while you scroll slides over it. Colours follow light and dark without being told, because the band reads the colour the strip is actually painted rather than holding a second opinion about it.

  The band keeps the strip's own colour for its first part and only then begins to fade, so the strip has an edge to sit on instead of starting to dissolve at the first pixel. How far down the fade begins is a setting, and a page may name a third colour part of the way through it — two colours fade in a straight line through whatever lies between them, which from white to a saturated green runs through a grey-green nothing in the palette is. The calendar now goes by way of the pale green of its own ramp, so the whole band stays in the greens.

  A page whose *first* block is a colour of its own can send the fade there instead: the calendar opens with the green band saying what day it is, so the fade arrives at that green and the two meet seamlessly. Fading to the grey behind it would not have removed the line, only moved it down by the height of the band. That is a separate setting from the page's background on purpose — a page claiming to be green to get a green fade would turn green the day somebody removed the block that was covering it.

  Every page that paints a background of its own now says which — the media shelves, the calendar, the film wall, the file browser and the search page all have one, and they are not all the same colour. Without that the band would fade to the colour the page used to be and leave a line where it was supposed to remove one.

- **Die Startseite ist jetzt eine Wand statt einer Tabelle**: every door was the same size, which says every door is the same and gives the eye nothing to land on. The tiles now come in four sizes — a square, a wide one, a tall one and one large one — dealt out fresh each time the app is opened, in a shuffled order, with a few deliberate gaps left between them. The gaps are the point: they are what makes it a wall rather than a slab. Nothing is placed by hand, because which tiles somebody sees follows from what they are entitled to and a layout drawn by hand would have a hole in it the moment one was missing — so the arrangement survives a page with two tiles on it as well as one with twelve. At most one tile is ever the large one, and the calendar is never made wide, since its date block wants height. On a phone the shapes still vary but the gaps wait for a wider window, where two columns would make one gap half a row.

- **Die Medien-Kacheln zeigen jetzt, was dahinter liegt**: the four media areas on the front page were flat coloured squares with a word on them, which is a menu written as a grid. Each now carries a photograph of the thing it holds — Schmalfilmrollen for Super 8, Kinosessel for die Mediathek, Plattenkisten für Musik, ein Zeitschriftenstapel für Zeitschriften — so the grid can be read at a glance instead of word by word. Verwaltung and Familie keep their colours, which is also what separates the two halves of the page.

  The pictures move, a little. One grows slowly under the pointer, presses in when clicked and comes back, and drifts against the page as it scrolls past. Each is the smallest movement that still reads as a response — a grid of squares all breathing at once is a screensaver. The labels wear their outline permanently on a photograph rather than only on hover, since a picture is not one colour and white on a pale corner is legible in the way a thing can be legible and still not be worth reading.

  The labels have been given a little weight of their own, on every tile rather than only the photographed ones: scrolling swings them, and stopping settles them back where they belong — the faster the page moves, the further they go. Each tile answers with a strength of its own, so the grid ripples rather than sliding about as one slab; twelve labels moving in exact unison read as a single object rather than twelve.

  Asked not to animate, the pictures stay and all three movements stop, and the labels do not swing at all. The colour each tile always had is still there behind its photograph, which is what shows while the picture loads and instead of it if it never arrives.

- **Der Inhaltsbereich liegt jetzt unter `/content`**: the CMS's editing shell became a module with a bar of its own — where you are, which piece of work your next save belongs to, and how much is waiting to be published — and it lives at `/content` rather than `/entries`. The tile on the front page and the entry in the menu lead there; old links to `/entries` and `/drafts` no longer resolve. The count of unpublished work moved out of the app's bar into that module's own, where it is next to the things it is about and does not take room on screens that cannot save anything.

### Fixed

- **Der runde Knopf oben rechts läuft nicht mehr grau an**: on an iPad the top third of that button looked smeared with grey, and no setting removed it. The cause has now been measured rather than guessed at. The system lays a blurred band over the top of the screen, and that band reaches about thirty pixels further down than the strip the clock and the battery sit in. On an iPad, where the page does not reach under the clock at all, those thirty pixels are the whole of it — which is why the same app looked right on a phone and wrong on a tablet, and why every earlier attempt fell short by exactly the same amount: all of them were sized from the clock's strip, and that strip is zero there.

  The band still cannot be switched off, and clearing it by moving everything down would cost thirty pixels at the top of every page on the device that was already fine. So the button gave up its white disc instead. It is the three bars and nothing behind them, taking the colour of the strip it sits on, which is what the way back beside it has always done. A blur over a white circle on a dark band is the strongest edge on the screen; over three thin bars there is almost nothing for it to take hold of.

- **Die Statusleiste auf dem iPhone ist nicht mehr hell**: installed on a phone, the bar with the clock and the battery in it took its colour from whatever happened to be at the top of the page — a white sliver on a grey app, and on some pages one colour before you scrolled and another after. Four things had to be true at once for the app to be able to decide it, and the last of them was not obvious: the colour has to be painted both on the strip and behind the page, because the system looks at the strip once you have scrolled and at the page itself when you have not. It is now black everywhere, or whatever colour the page asks for, and the clock and battery turn light against it.

  The haze that sits over the top of a scrolling page is a separate thing and still there. It belongs to the system, nothing a web page can write turns it off, and seven attempts over three weeks established that. What the app does instead is keep the top of the screen flat and empty, so there is nothing up there for it to blur.

- **Der Film bleibt beim Scrollen ganz sichtbar**: in a series, the player stays at the top while you scroll the list of episodes — and it was sticking to the top of the window rather than to the underside of the app's own bar, so the first inch of the picture disappeared behind it. The same was true of the shelf in Musik. Both now stop where the bar ends.

- **Aus einem Film, einer Ausstellung, einer Person oder einem Werk führt wieder ein Weg heraus**: those four pages are shown full width and carried no navigation at all. In a browser the back gesture rescued you; installed, with no address field and no back button, they were dead ends — the only way out was to close the app, which reopens it at the front page. They have the app's bar now, with the name of the thing you are looking at in it.

- **Zeitschriften werden in der App gelesen**: installed on a phone, the app runs without Safari's bars — no address field, no back button, and no pulling down to reload. Opening a scan therefore replaced the app with the document and left nothing to return with: the only way back was to close the app altogether, which starts it again at the front page rather than where you were.

  An issue now opens inside the app: the sheet slides up from the foot of the screen and covers everything, the app's own bar included, because reading a magazine is the whole screen's job. Its header says which issue it is and closes it again, and closing puts you back on the shelf exactly where you were standing.

  Which reader opens an issue can be switched on the shelf — the app's own, or handing the file to the system viewer — so the two can be compared against real scans rather than argued about. Either way there is a way back: the system viewer is given a window of its own rather than this one, so the app is still standing behind it. The pages are drawn as they are reached rather than all at once, and only a handful are kept drawn at a time — a hundred pages held as pictures is more memory than a phone will give a web page. Nothing downloads the whole file either: only the pieces being looked at are fetched, which is what makes opening page one of a ninety-megabyte scan cost a page.

- **Neu laden, wenn es sonst nichts gibt**: for the same reason — an installed app has no reload — the menu now offers one, and only there. A page that has got itself into a state can be reloaded where it stands instead of by closing the app and losing your place.


- **Anyone could read the server's configuration file (security fix)**: the route that serves videos from a folder on the server built the filename by gluing the requested path onto the folder name. A request that spelled "go up one level" in its escaped form — which the web server passes through already unescaped — therefore reached files outside that folder, and the route requires no sign-in. The working directory is the one holding the application's settings file, so the session key, the single-sign-on secret, the image-service keys, the administrator token, the storage credentials and the database password were all readable by anyone who knew the address. The path is now opened through a mechanism that refuses to leave the folder at all, including by way of symbolic links, and anything outside it is reported as simply not found. **Every secret in that file should be treated as exposed and replaced.** Ordinary use of the route is unchanged.

### Added

- **Bildweise durch einen Film**: under the player there are now four handles — a second back, a frame back, a frame forward, a second forward — with the position beside them written to the frame rather than to the second. It is for landing on an exact moment, which is what a scene's start time has to be, and pressing one pauses the film first: stepping a frame at a time while it is still running is not stepping.

  A frame here is a real frame. Super 8 ran at 18 pictures a second, so one lasts 0.0556 seconds, not the 0.05 the old buttons used — close enough to look right and wrong by a whole frame every eighteen presses. Films in a format whose rate is not recorded get no frame handles at all rather than handles that step the wrong distance.

- **Super-8-Filme laufen von selbst los**: a Super-8 film now starts playing as soon as its page opens, as it did in the old app. It was shot on silent stock, so there is nothing to hear and nothing to be startled by — which is also the reason a browser allows it to start at all, since browsers will only begin playing what makes no sound. Films in any other format wait to be asked, because a format with sound is a different question and the field that records the format exists precisely so it can be answered separately.


- **Der Kalender ist wieder erreichbar**: the front page has offered a Kalender tile and the menu a Kalender entry for some time, and both led to a page that did not exist. The frame is now there: a green band saying what day it is — the month, the calendar week, the year, the day and the weekday — with each part a link to the page for that part, and routes for a year, a month, a day and an ISO week nested inside it.

  There is a date picker beside the band, too — pick a day and it goes to that day, page to another month and it goes to that month. The old page had reached for one and never got it: it referenced a calendar library that was not installed, so that half of the band simply stayed empty. This one is the component the app already ships.

  What those four pages show is still a placeholder naming the part of the date it was reached by, exactly as the earlier, abandoned attempt left them. That is deliberate: they mark where the work resumes rather than pretending to be a calendar.

  Two things the old version got wrong are fixed on the way. The month link pointed at the month before it, because it used the computer's month numbering, where January is zero. And the calendar week never appeared at all — the value it was read from had been left as the word "tag" — so the week pages could not be reached from anywhere. The week is now worked out properly, including the awkward days at the turn of the year, where the last days of December can belong to the first week of the next year and the first days of January to the last week of the previous one.

- **Die Kalender-Kachel zeigt das Datum**: the tile on the front page is no longer a green square with a word on it — it shows today exactly as the calendar page does, in a size that suits a tile, and each part of the date leads to the same page it leads to there. It is the calendar's own block rather than a copy of it, so the two cannot come to disagree about what day it is.

  Its background is the whole green scale the stylesheet defines rather than one green out of it: pale at the top, deep at the foot, so the square has depth instead of being a flat fill, and the whole ramp drifts slowly down the tile and back. Everything written on it is outlined, which is what lets the same text sit legibly across that range. For anyone who has asked their system not to animate things, the colours stay and the drifting stops.


- **Die DJ-Sets sind wieder da**: the mix series on the family storage can be listened to in the app. The overview shows each series as a row of sleeves that scrolls sideways and comes to rest on a whole CD rather than between two; a series opens as a wall of its CDs, and a CD shows what is on it beside its sleeve and the photograph of its tracklist. The titles come from inside the files — these were written with their names in them — and fall back to the filenames, which in this collection are frequently a number and nothing else.

  The old page for this never worked: it asked an address that no longer exists, so it drew an empty list between two broken images, and each track linked to the file browser rather than playing. The layout was right, and is what has been rebuilt around.

  Access is its own permission, `djvet`, rather than the music one: the two are different collections, and being allowed to hear the family's records says nothing about who should hear its sets. Which folder holds them is the `DJVET_ROOT` setting, its own again, so a mistake in one set of routes cannot reach what another serves.

- **Angefangene Musik läuft weiter, wenn man weiterklickt**: the player used to live on the music page, so leaving it stopped the sound mid-track. It now sits outside the pages entirely — start an album, walk off to the magazines or the films, and it keeps playing. On the music and DJ pages it is the full bar along the bottom, with the sleeve, what is playing and the way to the next track; everywhere else it shrinks to a small pill in the corner, out of the way but still one click from silence. Nothing at all exists until something is played, so a visit that plays nothing costs nothing.

  What it plays is now a list rather than a single track, which is what lets it go on to the next one by itself: before, finding the next track meant searching the page that had been left behind.


- **Der Footer erscheint jetzt auch in der Tipprunde — aber nur für Familienkonten**: someone who reaches the pool from the rest of the app now finds the usual footer at the bottom of it, which is the way back: the areas they may visit, their session, their account settings. For a pool player the page is exactly as it was. That is not a cosmetic distinction — a pool account is *confined*, meaning the server grants it the pool and refuses it everywhere else, so a footer would have shown them an empty list of areas and a set of links that bounce whoever clicks them. The test is whether the account is entitled to anything besides the pool, which is the question the footer actually answers: is there somewhere else for this person to go? A visitor with no account sees no footer either.

- **Die Musik ist wieder da**: the albums on the family storage can be played in the app again — a wall of sleeves, nothing else, because an album is recognised by its cover and the name of every one of them at once is noise. The bar above the wall carries the way back, a filter, and a slider that sets how large a cover is; an album opens over the wall rather than on a page of its own, showing its sleeve and, under it, what is on it, and closing it puts you back where you were looking. The play button on a sleeve starts the album, a track in the open window starts there, and what is playing keeps playing while you carry on browsing.

  There are no artist names anywhere, which is deliberate twice over: the storage does not record them — a folder is called "1987 - Appetite For Destruction (lameV3A)" and that is all there is — and reading them out of the files would mean opening every file on the shelf to draw a page of pictures. What *is* read out of the folder names is the year and the title, with the encoder the rip was made with dropped, since that is a fact about the file rather than the album. A trailing bracket is only removed when it reads like an encoder, so *Live At Budokan (Remastered)* keeps its name.

  An album here is a folder with no folders inside it, rather than a folder with music inside it. That sounds like a detail and decides something visible: several albums on the shelf are a sleeve and no tracks yet, and the other rule would have made them disappear instead of showing them as what they are.

  It needs a setting, `MUSIK_ROOT`, naming the folder the albums live in, and its own permission, `musik`, on the same reasoning as the archive's: listening to the family's albums does not follow from watching its films.

- **Ein Titel sagt nur, was die Platte nicht schon gesagt hat**: under each track the window showed everything its tags carry — artist, album, year, genre — which on an album by one artist meant the same four things repeated on every line, directly beneath the heading that had just said them. A row now carries only what *differs*: the guest on one song, the compilation where the heading can name no single artist, a track filed under a year the rest of the album does not share, a second album inside one folder. An album whose tracks all agree with its heading shows nothing further, which is the right amount to say about an album that has nothing further to say.

- **Die Titel sagen jetzt, wie lange sie dauern**: the track list showed how large each file is, and the album's running time was a guess worked out from those sizes — "ca. 35 min" for an album that in fact runs 40:14, twelve per cent out, because it assumed a bitrate the encoder was never obliged to keep to. Now every track shows its actual length and the album its actual total, exactly.

  It costs nothing. The length is in one of two places, both of which lie in bytes already being fetched to read the tags: a frame in the tag that states it outright, and — where that is missing, which is half this shelf — the count of audio frames that a variable-bitrate file keeps in its first frame, which with the sample rate gives the length precisely. The only change was to read two kilobytes further than the tag's end, so the second of those comes along with the first. All sixty-four tracks on the shelf now report a duration, and the two that could be checked against a player agreed to the second. A file that says nothing still says nothing: the estimate remains for that case and is still labelled as one.

- **Das Musikregal, nachgebessert nachdem es zum ersten Mal jemand gesehen hat**: several things were wrong that only looking could find. On a phone the filter box shrank to nothing — it was the one control in the bar allowed to give way, so it gave way entirely and left a field that was there, focusable and invisible; the bar now wraps onto a second line instead. Switching between the two ways of reading the shelf blanked the wall and replaced it with the word "loading" for the eleven seconds a search takes, even though both readings produce the same albums — the covers now stay put and only the cost readout blanks, since crediting one reading with the other's measured time is the one thing that page must not do. The album's title was printed twice, once in the window's header and again beneath it. And "Dateinamen" showed the same list as "Tags", because the titles read out of the filenames are what the tags already fall back to — it now shows what the file is actually called, which is what the label says and the only reading that shows anything.

- **Die Platten sagen jetzt selbst, von wem sie sind**: the folders on the shelf carry a year and a title and nothing else — the *artist* appears nowhere in the layout at all, and there is no level of folders to put one in. It is inside the files, and opening an album now reads it from there: Guns N' Roses, Alice Cooper, the genre, and the titles as whoever ripped the album spelled them. The track list can be switched between those and the filenames, because the two disagree in both directions and neither is reliably the better; the switch only appears where there is something to switch to, and an album whose files carry no tags lists and plays exactly as before.

  Reading them is deliberately frugal. A tag says how long it is in its first ten bytes, so rather than downloading songs to read their titles, the app fetches a few kilobytes from the front of each file and asks for more only when the file says there is more — which on this shelf means most albums are read in one request per track and the one with its sleeve embedded in the files takes two. An album is remembered for half an hour once read, so opening the same album twice in a sitting costs nothing at all. Measured against the shelf as it stands: 140 to 570 milliseconds the first time, nothing the second. A file that cannot be read is reported as untagged rather than failing the album it is part of — these are rips going back decades and some of them are strange.

- **Two ways of reading the shelf, switchable, so the better one can be found rather than guessed**: the storage offers two ways to find out what is on it and neither is simply better. Listing reads one folder per request — fast, twenty-five milliseconds warm, but one request per folder. Searching reads the whole shelf in three requests whatever its shape, but takes seconds, and the time does not follow the size of the answer: the whole of this shelf took as long as the whole of a drive holding a hundred times more. Against the six albums there now, listing wins by a factor of sixty-five — seven requests in 170 ms against three in 11 seconds — but that arithmetic turns on how many folders there are, and the shelf is about to grow. So both are built, the bar switches between them, and it prints what each cost. They are written to produce the same albums from the same shelf, because a comparison between two things that disagree about the answer compares nothing; that they agree is checked against the real shelf rather than assumed.

- **Das Zeitschriften-Archiv ist wieder da**: the scanned computer magazines on the family storage can be read in the app again — 136 issues of *Happy Computer* and *Power Play* from 1983 to 1991. Each year is a row of covers you scroll sideways, and the row comes to rest on a cover rather than half way between two; the specials, which carry no date, sit together at the end. What each row shows is read out of the filenames, because nobody ever wrote down what an issue is called: the year and month where they are there, the file's own name where they are not. One magazine turned out to be filed *inside* another on the storage, so the archive is walked rather than listed — a folder holding scans is a magazine wherever it sits, which is how the 43 issues of Power Play stopped being invisible.

  An issue is a scan of fifty to a hundred and twenty megabytes, so nothing is downloaded to show it: the covers are rendered by the storage from the first page, and they are fetched as they come into view rather than all at once. Opening an issue hands the request to the storage, which can serve several pieces of a document at once — that is what a reader does when it jumps to a page, and answering it the cheaper way would mean sending the whole magazine to show one page of it.

  It needs a setting, `RETRO_ROOT`, naming the folder the archive lives in, and its own permission, `retro`, which is separate from the Mediathek's: reading old magazines and watching the family's films are different things and neither follows from the other.

- **Files from the family storage can now be played rather than only fetched**: video and audio kept on HiDrive were served by asking the storage provider for a temporary link and passing the request along to it. That works, but it asks for a fresh link on every request — and a video being scrubbed makes one request per jump, so every jump paid for it. There is now a second way to serve the same files in which the app reads the bytes itself and remembers what it knows about a file for a minute, which was measured at roughly twice as fast to start playing (44 ms against 104 ms on a 45 MB film) with everything else — seeking, resuming, caching — behaving identically. It also keeps the key to the storage on the server: the older route hands the browser a link that works on its own until it expires, which is fine for downloading a document and less so for a private archive. Both remain, because they turn out to be good at different things. The older route asks the storage provider for a temporary link and passes the request along, which means the provider answers — and it can answer a request for several separate pieces of a file at once, which the new route deliberately does not. A document reader opening a large PDF does exactly that, so downloads and documents keep the older route. It is no longer slow: the temporary link is now remembered for a couple of minutes instead of being asked for on every request, which measured 22 ms per request against 160 ms before. A link the provider has stopped honouring is simply replaced and the request tried again, so remembering it cannot break anything — the app checks before any of the answer has been sent.

- **A home for the shared video library**: a new setting, `MEDIATHEK_ROOT`, names one folder on the family storage that holds videos everyone may watch, and two endpoints serve it — what is in a folder, and the bytes of a file. Unlike the file browser, which shows each person their own storage, this is one shelf that looks the same to everybody. Three things follow from that and are the reason it is separate rather than a corner of the browser: the permission to watch is the only thing standing in front of it, so being allowed to browse your own files neither grants nor is required for it; the responses can be cached by address, because an address means the same file for every viewer; and the folder is the boundary — nothing outside it is reachable, including the rest of the same storage account, so a mistake in one route cannot reach another's files. Left unset, the endpoints answer that no library is configured rather than vanishing, so a deployment that forgot the setting does not look like one without the feature.

- **The shared video library can be watched in the app**: the Mediathek is a wall of covers — eight series, picked out by looking rather than by reading — and behind each one a page built around the player. The player stays at the top of the window while the rest scrolls under it, which is what the fortieth episode of a forty-one episode series needs; it shows the picture at the size it was actually recorded, on black, with the cover and the episode list side by side underneath. The bar between them carries the way back, what is playing, and two things the player itself does not offer: filling the window's width, and filling the screen. Each episode names itself on one line and describes itself on the next — how large the picture is, what kind of file it is, and how big — which is also what tells two copies of one episode apart. Everything the pages show is read out of the folder itself: which folders count as series, what to call them, what each episode is called and which of several copies of it to offer. Nobody ever wrote those conventions down, so each is a reading of what the shelf actually looks like rather than a rule it follows, and each is noted in the code where it is already known to be wrong — which is also why the reading is done in the browser, where correcting it costs nothing.

  Two of those readings are worth naming. A count of files is not a count of episodes: one series keeps its first episode four times and spells its name inconsistently between the copies, so the copies are gathered by the episode number in front rather than by the name, and offered as a choice of copy rather than as four episodes. And that choice is labelled by file size, not by the resolution the filenames advertise — all four are in fact the same 702 by 406 picture, and the one calling itself 2160p is the *worst* of them, so believing the names would have confidently handed out the poorest copy. The archive masters are left out entirely: they sit beside the viewable copies, outnumber them in one folder, and no browser can play them, so listing them would have filled the page with rows that open and then play nothing.

  A library that is not set up, an account that has not been given the area, and a real fault all used to arrive as the same "it did not work"; each now says which it is, so the one that is a forgotten setting reads as a forgotten setting.

- **The application's own developer documentation is now browsable from inside it**: a yellow box on the start page opens the reference for every Go package this app is built from — what each one is for, what it offers, and the source behind it, browsable inside the app rather than as a separate site. It is generated from the code itself, so it cannot drift from what the program actually does, and it is read out of the running program rather than from a checkout, which means it matches the version that is deployed rather than whatever happens to be on someone's machine. Signing in is required: the source is not secret, but it is not part of the public site either. Both halves come from the CMS — the part that reads the code and the pages that display it — used directly rather than copied, so the two applications cannot drift apart and a fix in one is a fix in both. It needed no new third-party dependencies at all.

### Changed

- **One sign-in for the family app and the tipping pool**: the two used to be separate — an account here, a different account there, two forms, two passwords, and a front page that offered only the pool, keeping everything else behind a marker cookie so that somebody who came for the tipping was not met by a sign-in for an account they do not have. There is now one form, on the front page, and it takes either. Somebody who plays in the pool types the username and password they have always used and is signed in; an account is made for them behind the scenes the first time, and from then on their password lives here. Nothing is asked of them and nothing is announced.

  Such an account is limited to the pool and refused everywhere else, so nobody reaches the family app by having played football tips for twenty years. Somebody who is both keeps their ordinary account and everything it opens. The pool's own credential is no longer handed to the browser at all: it is made fresh for each request the app forwards on someone's behalf, which means signing out ends it, nothing is left behind on a shared machine, and there is nothing to expire.

  **Anyone still signed in through the pool's old form is signed out once** and needs to sign in again here. Sign-ins made the old way left a credential in the browser that lasted weeks; continuing to honour it would have been a second way in that needs no account, outlives signing out and cannot be taken away. One sign-in each is worth that.

  Two smaller things follow. **A password can now be changed from the app**, which it never could — only an administrator could set one, and that would have left everyone arriving from the pool stuck with a password they chose years ago. And being asked to sign in halfway through something now returns to the front page, where the form is; it used to point at an address that has never existed here and only appeared to work by accident.

### Added

- **The files on HiDrive can be browsed in the app**: folders and their contents, with the size, dimensions and date of each entry, a trail back up, and the pictures of a folder shown as pictures rather than as a list of filenames. A single file can be looked at and downloaded. It is its own area, so it appears only for an account that has been given it — having storage configured is not by itself permission to go through it, and an account that has been given the area but has no storage of its own is shown the family's.


- **The football pool is served from here**: Geheimtipp — the tipping pool that has lived at ihleven.de — is now rendered by this app: the current matchdays, a matchday's tip matrix with every tipper side by side, the day's and the overall standings, the league table, the list of matchdays, and the ranking with everyone's avatar and motto. The tips themselves still live in the pool's own database; only the pages are new.

- **Tips can be placed again**: on a matchday, your own column is typeable until each match kicks off — every other column stays as it is, and a match whose kick-off has passed stops taking anything. One *Abschicken* sends the whole matchday at once, and the pool answers per match, so tips it takes are kept even when one of them comes too late. A single match can also be tipped on its own page, with the same up-and-down buttons the pool has always had.

- **Results are entered in the app**: on a matchday, whoever keeps the pool's results gets a field per fixture instead of the printed score, and one button saves the lot — which rescores everyone, so the standings and the league table beside it are re-read with it. Fixtures not yet played keep their placeholder rather than being cleared. Nobody else is offered the fields, and the pool refuses the save from anyone else regardless.

- **A page for each match**: the two clubs over a photograph with the result between them, arrows to the match before and after, and underneath it every tipper's tip with the points it earned, best first.

- **Registering for the edition**: name, motto and a picture — chosen from the pool's collection or uploaded. Signing in and being registered are two different things, and trying to tip without the second now says so and offers the way to fix it, instead of being refused by the server without explanation.

- **A changed name, motto or picture shows up straight away**: previously the registration page saved, and the ranking and the matchday headings went on showing the old one until the page was reloaded — the same thing happened on the old site. A tipper is described in two places at once, and only one of them was being re-read.

- **The avatar page shows tiles or a list**, whichever is wanted: the tiles for picking a picture out, the list for reading what a picture actually is — who it belongs to, its size, format and when it arrived. The old site had only the list.

- **Two menus, one per thing they belong to**: the header over the grass carries the account — who is signed in, and the way out — and stays the same on every page of the pool whatever edition is being read. The bar below carries the edition: its pages, its name, and the registration this person plays it under, with their picture, name, motto and the way to change them. Signing out is offered once, where the account is, rather than in both.

- **The pool has its own sign-in**: whoever tips signs in with their Geheimtipp account, not with the one for the family site. The two live at the same address and have nothing else in common: an account here grants nothing there, and the other way round. Someone signed in sees their own column first — on a phone it is the only one shown, because nobody can read twelve columns of scores on a phone anyway.

- **A new account can be set up without a terminal**: creating one, giving it a first password and handing over an invitation link are all in the app now. Registering a device still asks for that password, as it always has — the link says who, the password proves it is them, and the two are meant to reach the person by different routes.

- **Accounts can be administered from the app**: who may sign in, what each person gets to see, and what they sign in with — all of it now in a "Konten" section instead of only at a terminal on the machine holding the database. An account is created, given its areas, and handed an invitation link; it can be locked without being deleted, signed out everywhere, or have a lost device removed. The section only appears for an account that has been given it, and the server refuses the same requests it hides, so the two cannot disagree. Setting up the very first administrator is still a command-line job, as is any situation where the app itself is what is broken.

- **The family films are a kind of content in their own right**: a film is now described the way a film actually is — which format it was shot on, when and where and by whom, how long it runs, a description, and a still to represent it. It replaces a description built around one particular storage path, so the archive can hold an 8mm reel or a video tape later without anything being redesigned.

- **Films are divided into named scenes**: a reel is a series of runs of the camera, and each one can now be given a name, a starting point and a description. The player offers them as chapters, using the browser's own chapter support rather than a hand-built imitation of it, so jumping to "Bescherung" works the way chapters work everywhere else. Only the starting point has to be given: a scene runs until the next one begins.

- **People and places can be marked in a film, at the moment they appear**: an annotation says that someone is visible from here to there, and optionally *where* on the picture, so a name can be shown next to the person it belongs to. Positions are recorded as a fraction of the frame rather than in pixels, so they stay correct however large the video is displayed. An annotation lasts five seconds unless an end is given. Names are free text — a contributor can write a name nobody has an entry for, or an uncertain one — and they are searchable, so "which films is Oma Anna in" is a question the archive can answer. Each annotation records who added it, in preparation for letting the family add them.

- **An editor for films**: the film, its scenes and its annotations are edited beside a video player with a proper transport — play and pause, and steps of half a second, a tenth and a hundredth, with the exact time shown to the millisecond, so a scene boundary can be placed precisely. A time can be taken from wherever the video is paused, any time in the lists jumps the video there, and an annotation is placed on the picture by clicking it. The same controls are on the keyboard.

- **A page showing all the films**: a list, or a wall of stills in one of three shapes — 4:3, square filled, or square with the whole frame fitted inside. The background can be light or dark. A film with no chosen still is represented by a frame taken from the film itself, so the wall looks like something without anyone having had to pick pictures.

- **Each account sees only the areas it has been given**: the parts of the site — films, content, family, calendar, media library, music, search — are now granted per account rather than being the same for everyone. The navigation, the start page and the links all follow what an account actually has, so someone given only the films sees only the films, and a visitor who is not signed in sees nothing. This hides areas rather than sealing them off; it is about not offering people doors that are not theirs.

- **The app can be added to an iPhone's home screen**: opened from there it runs without the browser's address bar and toolbar, with its own name and icon. Nothing about how updates reach people changes — a new version is picked up the moment it is deployed, as before.

- **A command for checking the storage connection**: `ihlvn hitoken` reports which storage accounts the app holds credentials for, whether each one still works and when it expires — so a failure to play a film can be told apart from a failure to reach the storage provider without guessing.

### Changed

- **A film is addressed by which film it is, not by where its file sits**: previously the page was handed the path of the video inside the storage provider and asked for it by that path, which put the storage layout into the address bar and into the page's source. Now the page asks for the film, and the server looks up where the bytes are. Nothing about the storage arrangement reaches the browser, and moving a file is a change to the film's entry rather than to every link that pointed at it. Measured on the same film, it is also faster to start playing — the previous route asked the storage provider for a fresh address on every single request, including every jump within a video, and that round trip is gone.

- **Signing in and out moved out of the top bar and into the menu**, which is now reachable at every window size rather than only on a phone, and is split into where you can go on one side and who you are on the other. The account details are shown directly instead of hiding behind a hover menu.

- **The site's name appears in the footer on every page** and, in the top bar, gives way to a way back when you are watching a single film.

### Fixed

- **An account granted everything was reported as being granted nothing**: `*` means "all rights", and the admin commands listed it as a right this build does not know, warning that it would grant nothing. It grants everything, including every area of the site. A right that genuinely is unknown is still reported.

- **Signing in with a passkey failed in some browsers** with "no ceremony is in progress". A browser can have two sign-in attempts open at once — one offered quietly in the username field, one started by the button — and the app could only remember one of them, so whichever finished second found nothing waiting for it. It also forgot the attempt before checking it, so a single mistyped or cancelled attempt broke the next one. The page now says which attempt it is completing, and the app only forgets an attempt once it has succeeded. Safari happened not to hit this; Chrome did.

- **The app no longer hammers the storage provider with expired credentials**: when refreshing its access to the storage provider failed, it retried immediately and indefinitely, and could throw away the long-lived credential by overwriting it with an empty one from a failed response. The provider noticed the traffic. It now waits longer between attempts, keeps the long-lived credential when a response does not repeat it, and stops entirely when the provider says the credential is no longer valid — which is a situation a human has to resolve, not something retrying can fix.

- **Captions in the film player never actually appeared**: every caption in every film was stored without any timing, and the player was reading those timings in a format they were never written in, so it produced captions that began and ended at no time at all. The timings existed all along in a second, separate field. Scenes now carry them, and the player uses the browser's own mechanism to display them.

- **The still shown for a film in listings was pointing at an address that no longer existed**, so film listings showed broken images. Listings now ask for the film's own still.

- **Previews in the film list were stretched**: the preview box is wider than it is tall in a different proportion than the pictures, and nothing told the picture how to fit, so every one was squashed.

### Removed

- **The browser is no longer given a key to the storage provider** (security): on signing in, and on every session check, the app handed the browser an access token for the cloud storage account, in a cookie. Nothing used it — the feature it had been added for was gone — so it was an unnecessary copy of a credential sitting in every visitor's browser. It is gone, and with it the sign-in code's knowledge of the storage provider entirely.

- **The old Super 8 content type**, together with its editor, its preview card and its page, replaced by the film described above.
